# 여울목의 등불 — 튜토리얼 프로토타입

## 렌더링 및 확장 맵 업데이트

- 맵을 28×18(504타일)에서 56×36(2,016타일)로 확장했다. 가로·세로 각각 2배, 총 면적 4배다. 건물의 실제 크기는 유지하고 건물과 주민의 위치 간격을 2배로 늘렸다.
- 시작점, 두 진영 인물, 몬스터, 잔해, 구조 후 복귀점, 정화 후 인물 위치, 충돌 경계와 미니맵을 함께 갱신했다. 이동 속도는 초당 3.8에서 5.2월드 단위로 조정했다. 필수 전투는 여전히 3마리이며 5분 이내 진행을 목표로 한다. 확대 후 실제 시간은 플레이 확인이 필요하다.
- 월드 렌더링 → 절반 해상도의 밝은 부분 추출 → 가로·세로 블룸 흐림 → 색 보정·비네트·가장자리 완화 → 한글 UI 순서의 후처리를 추가했다. 월드 내부 해상도는 1280×720이다.
- 건물·나무·캐릭터에 공통 광원 방향의 부드러운 투영 그림자와 접촉 그림자를 추가했다. 2.5D 지면용 그림자로, 3D 그림자 맵이나 물리 기반 전역 조명은 아니다.
- 주인공과 주민은 실행 시 생성되는 8방향×8프레임 RGBA 스프라이트 시트를 사용한다. 주인공의 걷기에 다리·팔·몸통 움직임이 적용되며 주민은 대기 자세와 플레이어를 향한 방향 전환을 사용한다. 공격은 별도 검 궤적, 회피는 잔상으로 표현한다. 정식 아트 에셋 대신 코드로 생성하는 임시 스프라이트다.
- 셰이더 기반 잔디·돌길·벽돌/회벽·기와·목재 재질을 추가했다. 건물에는 목재 보강대와 창 주변의 부드러운 빛을 더했다.
- 호수에는 시간에 따라 움직이는 물결, 수면 반짝임, 빛무늬와 기슭 포말·갈대·물안개를 추가했다. 이동 시 먼지와 월드의 부유 입자도 표시된다. 수면 반짝임은 절차적 효과이며 건물의 실제 반사 렌더링은 아니다.
- `SimpleGame/TutorialVisuals.h`에 재질·후처리 셰이더와 스프라이트 생성 코드를 추가했다. 별도 라이브러리나 에셋 다운로드는 필요하지 않다.

확인할 화면: 마을의 기와·벽 재질과 캐릭터 걷기, 나무 아래의 그림자, 남쪽 호수의 움직이는 표면, 숲 정화 전후의 빛, 창 크기를 바꿨을 때의 화면과 한글 UI. 사용자 요청에 따라 이번 업데이트도 빌드·실행하지 않았다.

## 실행

`SimpleGame.sln`을 Visual Studio에서 열고 `SimpleGame`을 시작 프로젝트로 선택한다. 기존 구성인 `Debug | x64`로 빌드하고 실행한다. 새 진입점이 튜토리얼을 실행한다. 기존에 남아 있는 실행 파일은 새 소스를 빌드하기 전까지 이전 사각형 데모다.

- Windows PC / OpenGL 3.3 이상.
- 기존 FreeGLUT·GLEW 라이브러리를 그대로 사용한다. 실행 파일 옆에 플랫폼과 맞는 `freeglut.dll`, `glew32.dll`이 필요하다. 기존 `x64/Debug`, `x64/Release` 등에 배치된 파일을 사용한다.
- 화면 기준 1280×720. 창 크기를 바꾸면 16:9 비율을 유지하여 표시한다.
- 한글은 Windows의 맑은 고딕으로 텍스처를 생성한다. 별도 폰트나 이미지 다운로드는 필요하지 않다.
- 새 렌더러의 셰이더는 소스에 포함되어 실행 작업 디렉터리에 의존하지 않는다.
- 한글을 포함하는 새 소스는 `/utf-8`로 컴파일하고, 기존 미리 컴파일된 헤더와 문자 인코딩이 충돌하지 않도록 해당 소스만 PCH를 사용하지 않는다.

## 조작

| 키 | 동작 |
|---|---|
| Enter | 시작 / 대화 다음 / 완료 후 자유 탐방 |
| WASD | 화면 기준 상하좌우와 대각선 이동. 대각선 입력을 정규화한다. |
| E | 가까운 주민과 대화 / 대화 다음 / 잔해 조사 |
| J 또는 마우스 왼쪽 버튼 | 가까운 적을 향한 근접 공격 |
| Space | 마지막 이동·공격 방향으로 회피. 짧은 무적과 재사용 대기시간이 있다. |
| 1 / 2 / 3 | 잔해 정화 대화 마지막 페이지에서 방식 선택 |
| Tab | 세계관 수첩 열기 / 닫기 |
| Esc | 일시정지 / 계속하기 |
| R | 일시정지 또는 완료 화면에서 처음부터 다시 |

## 3~5분 목표의 진행

| 구간 | 예상 시간 | 행동 및 이야기 |
|---|---|---|
| 여울목 도착 | 20~40초 | 시작 설명을 읽고 미라와 대화. 휴전 27년과 그림자병을 소개한다. |
| 두 진영의 목소리 | 40~70초 | 레온과 사하에게 말을 건다. 공명기와 봉인 문양을 받고 양쪽의 책임과 상호 의존을 듣는다. |
| 숲으로 이동 | 15~30초 | Space 회피를 한 번 사용한 뒤 동쪽 숲으로 간다. 목표 표식과 미니맵이 방향을 안내한다. |
| 그림자 전투 | 20~45초 | 공격 예고 원을 피하며 그림자 3마리를 물리친다. 각 적은 기본 공격 2회에 쓰러진다. |
| 잔해 정화 | 25~40초 | 잔해 가까이에서 E. 과거 전쟁의 기억을 듣고 세 가지 방식 중 하나를 선택한다. |
| 귀환과 작은 축제 | 30~50초 | 미라에게 보고한다. 두 진영 인물이 모이고 등불이 떠오르며 튜토리얼이 끝난다. |

대사 읽기와 이동을 포함해 약 3~5분을 목표로 설계했다. 선택 대화와 자유 탐방까지 포함한 실제 플레이 시간은 사용자 플레이 확인이 필요하다. 5분 초과 시 강제 종료하지 않는다. 일시정지·수첩·비활성 창 상태는 진행 시간에서 제외하며 대화 읽는 시간은 포함한다.

## 주민 7명

- 미라: 국경 마을의 촌장, 시작과 완료를 담당.
- 레온: 아르켈 연방 조사관, 별의 마력과 연방의 책임을 설명.
- 사하: 바르카 연맹 길잡이, 자연의 상처와 회피를 설명.
- 도란: 두 진영의 재료로 빵을 만드는 상인.
- 나리: 서로 다른 깃발을 모두 좋아하는 아이.
- 오렌: 전쟁에서 동생을 잃었지만 상대 진영의 도움을 받아들이기 시작한 목수.
- 예나: 두 진영의 지식으로 치료하는 약초사. 대화 시 체력을 회복.

레온과 사하의 필수 대화는 어느 순서로 들어도 진행된다. 정화 이후에는 위치와 대사가 바뀐다. 쓰러지면 예나 근처로 돌아오며, 완료한 대화와 이미 처치한 적은 유지된다.

## 화면 표현

OpenGL에서 매 프레임 직접 그리는 도형 기반 2.5D 프로토타입이다. 아이소메트릭 바닥, 입체 지붕과 벽, 전경·후경 정렬, 나무, 물결, 그림자, 두 진영 깃발, 불빛, 별의 잔해와 부유 입자를 사용한다. 마을은 황토·녹색·등불의 따뜻한 색으로, 숲은 청회색·보랏빛으로 구분한다. 정화하면 숲 바닥과 잔해의 색이 변하고 마을에 등불이 떠오른다.

화면에는 체력, 현재 지역, 단계별 목표, 경과 시간, 미니맵, 상호작용 안내, 회피 대기시간과 한글 대화창이 표시된다. 긴 대사는 글꼴의 실제 너비를 기준으로 줄을 바꾼다.

## 구현 파일

- `SimpleGame/SimpleGame.cpp`: 창·입력 콜백·시간 기반 루프·초기화와 종료.
- `SimpleGame/TutorialGame.h`, `TutorialGame.cpp`: 월드, 충돌, 인물, 전투, 퀘스트 상태, 대사, 화면 구성.
- `SimpleGame/TutorialRenderer.h`, `TutorialRenderer.cpp`: OpenGL 3.3 삼각형 렌더러와 한글 텍스처·문장 캐시.
- `SimpleGame/SimpleGame.vcxproj`, `.filters`: 새 소스 등록 및 UTF-8 설정.

기존 `Renderer`와 `SolidRect` 셰이더는 보존되어 있으며 튜토리얼 실행 경로에서는 사용하지 않는다. 이번 범위는 단일 테스트 지역이다. 저장/불러오기, 인벤토리, 오픈 월드 청크 스트리밍, 음향, 정식 스프라이트 에셋은 아직 구현하지 않았다. 선택은 정화 이후 결말 문구에 반영되며, 장기적인 진영 평판 시스템은 포함하지 않는다.

## 사용자 확인 항목

사용자 요청에 따라 자동 빌드·실행 및 화면 확인은 수행하지 않았다. 아래는 직접 확인할 항목이다.

1. 새로 빌드하면 한글 시작 화면이 뜨는지.
2. WASD 대각선 이동, 건물·나무 충돌, Space 회피가 동작하는지.
3. 두 진영 NPC 대화를 반대 순서로 들어도 숲 단계로 넘어가는지.
4. 붉은 공격 예고 후 피해가 발생하고 회피 중에는 피해를 피하는지.
5. 그림자 3마리를 처치한 후 정화 선택 1·2·3이 각각 완료로 이어지는지.
6. 귀환 시 인물의 위치·대사와 숲의 색, 등불이 바뀌는지.
7. Tab·Esc·R, 창 크기 변경, Alt-Tab 후 입력이 정상인지.
8. 실제 읽기·이동 속도 기준으로 기본 진행이 5분 안에 끝나는지.
